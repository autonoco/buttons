# Management Meeting

## Objective

Deliver a decision-ready playbook grounded in internal evidence and current external practice. Make the recommendation explicit. Do not invent evidence, people, email addresses, document contents, or availability.

## Workflow

1. Restate the requested process as one concise topic. If the request contains multiple processes, ask which one to prioritize.
2. Search connected internal sources. Read the strongest Drive sources and relevant Slack discussions before summarizing them. Preserve source links and state unavailable-source gaps.
3. Consolidate supported facts: current process, tools, existing decisions, gaps, and uncertainty.
4. Research credible primary or expert sources. Compare 2–3 concrete options: mechanics, benefits, risks, adoption effort, and evidence.
5. Write the playbook: current state and gaps; options; main recommendation; first steps; owner; success signal; and decision checkpoint.
6. Create a natural voice-over script under 4,500 characters. Generate spoken audio only when the configured voice is available.
7. Create a populated deck with source links in speaker notes or a source slide. Generate one slide-synchronized review recording from the final deck; it is the review asset, not a standalone audio deliverable. Verify both before handoff.
8. Send the playbook and combined recording, then ask who should receive the presentation.
9. Schedule only when explicitly authorized:
   - Resolve attendee emails through the directory; never derive them from names.
   - Check all invitees' availability, propose 2–3 slots, and wait for explicit time confirmation.
   - Attach the final MP4 from the requester's private Drive to the calendar event; a Slack permalink or description link is supplemental only.
   - Create the invite with `guestsCanModify=true`. Verify saved attendees, time, links, and attachment. From the requester's attendee account, confirm the attached file resolves, is an MP4, and can be downloaded; ensure every other attendee has explicit Viewer access.

## Output

Lead with the recommendation. Include supported current-state findings, options, first steps, and source links. Label missing evidence or unverified integrations.

## Guardrails

- Keep Drive outputs private to the requester unless they explicitly request sharing.
- Do not schedule, invite, or message additional people without authorization.
- Do not create a GitHub issue unless explicitly requested.
- Do not treat filenames or search metadata as document content.
